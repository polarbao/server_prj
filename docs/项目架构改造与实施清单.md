# 项目架构改造与实施清单

本项目为 `hard2Ser_3_0`（本地硬件代理服务端）。当前代码在底层 `work` 与 `ipc` 模块中与 Qt 框架存在深度耦合，违背了“架构分层、非 UI 逻辑严禁依赖 Qt 特有类”的核心第一性原理。
为彻底解耦，为后续平滑接入 Motion Control SDK 以及微服务化铺平道路，特制定以下改造与实施清单。

## 第一阶段：核心阻断性重构 (P0 优先级)
**目标**：剥离底层对 Qt 事件循环与并发（`QThread`, `QMutex`, `QTimer`）的依赖，解决架构“伪分层”问题。

### 实施清单：
- [ ] **任务 1.1**：清理 `work` 模块（`workThdMgr`, `workBase`, `scanWork`, `stickWork`, `manuWork`）中遗留的 `<QThread>`, `<QMutex>`, `<QTimer>` 等无关头文件。
- [ ] **任务 1.2**：检查并移除 `ipc` 模块中的 `QTimer`（如 `TcpServerWrapper`, `CameraTcpMgr`），替换为标准 C++ 异步定时器或 `hv::Timer`。

## 第二阶段：数据结构与内存脱钩 (P1 优先级)
**目标**：消除底层对 Qt 专有数据结构（`QString`, `QList`, `QMap`, `QJsonObject`）的依赖。

### 实施清单：
- [ ] **任务 2.1**：在 `work` 模块中，全面将日志打印、字符串传递使用的 `QString` 替换为 `std::string` 和 `std::string_view`。
- [ ] **任务 2.2**：在 `ipc` 模块与网络解析中，清理 `QString` 和 `QMap`，转为 `std::string` 和 `std::unordered_map`。
- [ ] **任务 2.3**：移除 `work` 和 `ipc` 模块中的 `QJsonObject`、`QJsonDocument` 等，统一替换为基于 `json.hpp`（nlohmann/json）的纯 C++ 解析。

## 第三阶段：事件通信机制解耦 (P2 优先级)
**目标**：消除底层对 Qt 信号槽机制（SIGNAL/SLOT）的滥用，完成彻底脱穿。

### 实施清单：
- [ ] **任务 3.1**：移除 `workThdSig.h` 及底层所有类的 `QObject` 继承与 `Q_OBJECT` 宏。
- [ ] **任务 3.2**：基于 `std::function` 实现跨模块的回调（Callback）或发布订阅系统。
- [ ] **任务 3.3**：在 `ui` 边缘层接管 C++ Callback，利用 `QMetaObject::invokeMethod` 安全切换回 UI 主线程刷新界面。

## 第四阶段：新硬件扩展与集成 (P3 优先级)
**目标**：整合运动控制 SDK，探索微服务化与插件化。

### 实施清单：
- [ ] **任务 4.1**：构建纯 C++ 适配层 `ProtocolEventMapper`，承接上游下发的 C++ 结构体指令，并调用 `motion_control_sdk` 控制硬件。
- [ ] **任务 4.2**：探索将 `IODeviceBase` 封装为 DLL，实现硬件驱动的动态插拔（插件化）。
