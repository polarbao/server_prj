# hard2Ser 3.0 产品需求文档 (PRD)

> [!NOTE]
> 本文档定义了 hard2Ser 3.0 硬件智能数据服务中控网关的功能需求、业务背景、非功能性需求，并规划了短期（VSCode/C++完善与接口预留）与长期（Go语言重写与UI演进）的双阶段产品发布路线。

---

## 1. 业务背景与产品路线图

### 1.1 背景与痛点
在智能制造及物联网仓储现场，`hard2Ser` 充当**边缘中控网关**。现有 2.0 系统主要依赖 Visual Studio 构建，仅支持 WebSocket/HTTP。我们需要支持更多协议（TCP/UDP/MQTT/FTP），并提供本地持久化数据库及自愈功能。

### 1.2 产品双阶段演进路线 (Roadmap) [NEW]

为了平滑实现语言和架构转换，产品划分为短期与长期发布版本：

+-----------------------------------------------------------------------------------+

## 2. 核心功能需求

### 2.1 全协议网络抽象与接入 (Multi-Protocol Adapter)
支持并通过统一接口管理 **TCP、UDP、WebSocket、MQTT、FTP、HTTP** 六种协议通道。

### 2.2 本地数据持久化与流转服务 (Database Service)
引入嵌入式 SQLite 数据库，实现：
- 任务下发状态流转的事务记录。
- 离线任务排队与断网增量续传。
- 设备配置及拓扑表的本地缓存。

### 2.3 【短期兼容核心】本地 IPC 通讯接口需求 [NEW]
为了在长期计划中实现 Go 语言对 C++ 业务层的零侵入替换，短期 C++ 重构中必须实现：
*   **通信媒介**：网关必须支持基于 Local WebSocket / 本地 TCP Loopback (127.0.0.1) 的进程间通信通道。
*   **协议载荷**：定义标准的 **JSON** 报文交互接口（包括任务下发请求、任务取消、设备状态变更上报等）。
*   **控制反转**：UI 层与业务后台彻底分离为不同的功能模块，通过 IPC 进行消息解耦。

## 3. 工业级核心扩展模块

1. **看门狗与自愈模块 (Watchdog & Self-Healing)**：线程活性监控与自动断网重连。
2. **离线缓存与断网续传 (Offline Cache & Sync)**：断网时自动将上报数据写入 SQLite 队列，连通后批量补报。
3. **安全与加密模块 (Security & Cryptography)**：支持 TLS/SSL，对本地敏感 Token 进行 AES 加密。
4. **配置管理器与热重载 (Config Manager with Hot-Reload)**：支持参数边界校验的热加载。
5. **心跳与存活检测 (Keep-Alive & Ping-Pong)**：底层硬件延时与在线状况监控。
6. **状态机引擎 (FSM Engine)**：强类型的任务/设备状态跃迁控制。
7. **诊断与性能监控 (Metrics & Diagnostic Interface)**：通过 REST API 暴露内部并发、队列积压等监控指标。
